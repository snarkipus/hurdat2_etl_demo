# v0.2.0

This release modernizes the DuckDB HURDAT2 pipeline's tooling, verified output
publication, diagnostics, and distribution packaging. See the
[release procedure](https://github.com/snarkipus/hurdat2_etl_demo/blob/v0.2.0/docs/releases/README.md)
for artifact verification and the
[project README](https://github.com/snarkipus/hurdat2_etl_demo/blob/v0.2.0/README.md)
for usage and recovery details.

## Compatibility and behavior changes

- **Python >=3.13,<4 is required**, with development and CI pinned to 3.13.
  Setup uses uv and the committed `uv.lock`; Poetry is no longer required.
  Packaging uses PEP 621/Hatchling, and type checking uses BasedPyright.
- **Existing output requires `--replace`.** Each run builds a sibling candidate,
  applies packaged Alembic migrations, commits and verifies data, closes database
  resources, then publishes atomically. It does not destructively initialize,
  append to, or migrate the existing destination. Publication failures preserve
  old output and retain the verified candidate for deliberate manual recovery.
- Persisted counts must match accepted loader inputs, and every stored geometry
  must be a nonempty point with finite longitude in `[-180, 180]` and latitude in
  `[-90, 90]`. Coordinates are not repaired or wrapped: `270E` fails acceptance.
  Geometry remains WKT text, not a native geometry column.
- CLI diagnostics append JSON lines to `logs/pipeline.log` in the working
  directory, with run/stage/error context. Rich remains console-only; handler
  ownership and caller logging context are restored at run exit.
- UTC-aware timestamps are normalized to UTC before conversion to the naive
  database timestamp representation, avoiding host-timezone-dependent persistence.
  This fixes newly loaded data; it does **not** repair old databases.
- Rich progress now uses matching units for actual transform work; commitment is
  reported only after successful transaction exit. Dynamic paths/names are
  escaped. Summary bands describe peak recorded wind across all statuses,
  including below 34 knots, rather than assigning cyclone classifications.

## Verification and distribution

The preparation baseline passes 230 tests with 90.15% branch-measured coverage.
Distribution acceptance builds a wheel from the sdist, installs hashed locked
runtime dependencies in an isolated environment, and independently checks CLI
help, fixture values, and packaged migration state. CI covers Linux quality/full
suite/installed packaging and ten targeted Windows runtime/publication cases;
Windows coverage is not a claim of a full-suite run. Final release revision and
downloaded-asset evidence must be established during publication, not inferred
from these preparation results.

Release assets comprise a tracked-source archive, a full-history Git bundle
advertising only `main` and all tags, Python wheel and sdist, a separate
Dolt-native Beads history backup, and `SHA256SUMS`.
There is no PyPI publication or new release framework.

The explicitly approved public Beads backup supports internal rehosting. It is
separate from source history and Python packaging; see the release procedure
for isolated restoration and remote configuration. It is a point-in-time
snapshot taken before release publication, so the release issue may still be
in progress in the backup. Public synchronization records the final outcome.

The sdist now uses an explicit source/test/root-file allowlist, fixing default
Hatchling selection that could include ignored local state through nested
`.gitignore` files. Local caches, Beads state/backups/interactions, and agent
dependencies are excluded. Packaging regression coverage uses synthetic private
canaries, and installed-package acceptance rejects unexpected sdist members
before building the wheel. The Git source archive still includes tracked docs
and reference material; the sdist is intentionally lean.

## Known limitations

- Use one run per destination on an ordinary local filesystem with external
  writers stopped. Detected destination WALs and unsafe paths are refused;
  never delete an old WAL to bypass refusal. No network-filesystem,
  concurrent-writer, hostile-path, or power-loss/crash-recovery guarantee exists.
- Atomic replacement retains no automatic backup. Allow room for old output,
  candidate and transient state; extraction/transformation also materialize rows
  in memory. Unexplained crash leftovers are not verified recovery candidates.
- Spatial and package installation need network access or compatible caches.
  Unavailable Spatial fails acceptance rather than silently skipping checks.
- Existing skipped-record and last-wins storm deduplication behavior remains;
  zero accepted rows can pass. Verification is not a whole-source or
  meteorological quality audit.
- JSON logs have no automatic rotation or concurrent-run/audit guarantee and
  may contain paths, IDs and exception details. Review them before sharing.
