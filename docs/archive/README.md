# Historical Documentation

These files preserve the original project's planning and review history.
They are not current instructions, accepted OpenSpec specifications, or a live
Beads backlog. Commands, paths, line references, coverage figures, checkboxes,
and architectural assumptions may be stale. Preserve their contents as evidence
rather than rewriting them to appear current.

| Material | Historical role |

| [ETL_plan.md](ETL_plan.md) | Original phased implementation checklist. |
| [code_review.md](code_review.md) | Review findings and recommendations at the time. |
| [console_ui_issues.md](console_ui_issues.md) | Console UI issue analysis. |
| [ui_improvements.md](ui_improvements.md) | Console UI implementation retrospective. |
| [ETL_diagram.png](ETL_diagram.png) and [editable source](ETL_diagram.excalidraw) | Original conceptual architecture, not the new target-state proposal. |

The five Markdown documents were moved from `docs/`; the diagram pair was moved
from `ref/`. All seven retain their original contents. Historical references
inside them may refer to their former locations or an older code layout.
Assess any unresolved recommendation against the current code and approved
scope before creating work; do not automatically import old checklists.
